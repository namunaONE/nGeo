# v1.1 release notes — open-data reference edition

**Version:** 1.1.0 (DNPWC-deferred edition)  
**Date:** 28 October 2026  
**Status:** Reference data and peaks layer complete; protected-area and buffer-zone geometry deferred under D10.

## 1. What is new in v1.1

v1.1 is additive to the frozen v1.0 administrative atlas. It adds the national conservation estate and the high peaks as **reference layers** that sit alongside — not inside — the administrative hierarchy.

- **Peaks layer** — 51 point features: 8 main eight-thousanders, 6 official additional summits, 37 curated 7,000 m peaks. Point symbols only; no peak polygon, buffer or viewshed.
- **Non-spatial reference tables** — 22 core/provincial protected areas and 14 federal buffer zones, with published area, designation, authority, gazettal date, province/district and a "boundary pending" note.
- **Bilingual labels** — Nepali and English names, with attested/transliterated/pending status flags.
- **Web reference panel** — counts and a collapsible attribute table in the sidebar.
- **Print sheet 04** — A2 landscape peaks sheet with all 51 peaks, a side index sorted by elevation, and the 8 vs 14 status note.
- **Source register** — 25 sources with licence and intended use.
- **8-row evidence table** — source, URL, quote, confidence and recommended action for the 4 pending names and 4 high-priority district rows.
- **Machine-readable QA** — `master_qa.json` and `build/reference_qa.json`.

## 3. What is in this edition

- Web map: provinces, districts, local levels, gap polygons, plus the peaks layer and the reference panel.
- Print sheets: 01 (national A1), 02 (Bagmati A2), 03 (Kathmandu A3), 04 (peaks A2).
- Offline web bundle: no external basemap, no network requests.
- Bilingual interface and labels (Nepali / English).

## 4. What is deliberately not in this edition

- **No protected-area or buffer-zone polygons.** Under D10 the DNPWC request is deferred; the PA/buffer rows are published as non-spatial records only. No WDPA, `stepps00` or OSM geometry is used as a substitute.
- **No invented or traced boundaries.** Missing geometry is published as a non-spatial record with a "boundary pending" note.
- **No ward-level coverage.** Wards remain Phase 2.
- **No official Survey Department geometry.** That is a separate permission-dependent edition.
- **No climbing permits, routes, camps or safety information.**
- **No real-time data or external basemaps.**

## 5. Accuracy and licence notice

This is an **open-data reference edition**, not a cadastral, legal or survey-grade boundary determination. Protected-area and buffer-zone extents are indicative; peaks are point symbols.

- Boundaries: Open Knowledge Nepal, LocalBoundaries (CC BY 4.0).
- Peaks: Wikidata (CC0), Wikipedia (CC BY-SA 4.0), Himalayan Database (facts only).
- Protected-area figures: published DNPWC, Nepal Tourism Board and OpenDataNepal figures, compiled for this atlas.
- Projection: Albers equal-area, 27°N / 30°N; web geometry in WGS 84 (EPSG:4326).
- Accuracy notice visible in the web app and on every print sheet.

## 6. Known limitations

- Thulagi Chuli (7,059 m) has no Nepali attestation; its name remains `pending`. It is shown as a point with a pending-name badge.
- 7 peak names are transliterated, not attested.
- Protected-area and buffer-zone areas are published figures that DNPWC has not yet confirmed (Parsa buffer 298.2 / 285.3; Parsa core 637 / 627.39; Bardiya 507 / 327; Chitwan, Shuklaphanta, Khaptad, Dhorpatan alternatives).
- The 5,720.28 km² buffer total is the sum of 14 published rows and is not an official DNPWC aggregate.
- Peak labels in dense clusters (Kangchenjunga, Khumbu) use numbered keys; inline labels would collide.
- The official-geometry edition (Survey Department) is a separate, permission-dependent track.

## 8. Rebuilding

```powershell
cd maps\pilot
node build\prepare_reference.js
node build\make_peaks_web.js
node build\make_reference_web.js
node build\make_peaks.js
```

Then render `print/04_peaks.html` to PDF with Edge headless, and re-run `build/check_label_collisions.js` after any peak-list change.
